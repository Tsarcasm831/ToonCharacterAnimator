# Game Animation JSON Schema

This schema is the first browser-runtime format for animation clips generated by offline tooling. It is intentionally aligned with the current procedural animation system, where named `player.model.parts` entries receive direct Euler rotation updates.

## Example

```json
{
  "action": "idle",
  "fps": 30,
  "frameCount": 90,
  "duration": 3.0,
  "loop": true,
  "bones": [
    "hips",
    "torsoContainer",
    "neck",
    "head",
    "leftArm",
    "rightArm"
  ],
  "frames": [
    {
      "index": 0,
      "time": 0.0,
      "rotations": {
        "hips": [0, 0, 0],
        "torsoContainer": [0, 0, 0],
        "neck": [0, 0, 0],
        "head": [0, 0, 0],
        "leftArm": [0, 0, 0],
        "rightArm": [0, 0, 0]
      },
      "positions": {
        "hips": [0, 0, 0]
      }
    }
  ]
}
```

## Top-Level Fields

- `action`: Stable action name, usually matching the file name without `.json`.
- `fps`: Source/export framerate.
- `frameCount`: Number of frames in `frames`.
- `duration`: Total clip duration in seconds.
- `loop`: Whether sampling should wrap when normalized time reaches the end.
- `bones`: List of exported bone names.
- `frames`: Ordered animation frame list.

## Frame Fields

- `index`: Zero-based frame index.
- `time`: Frame timestamp in seconds.
- `rotations`: Required map of bone name to Euler XYZ radians.
- `positions`: Optional map of bone name to XYZ local position.

Scale is excluded for now. Add it only when a real animation requires it and the runtime has clear blending rules.

## Rotation Units And Order

Rotations must be Euler XYZ radians because the current runtime directly mutates:

```ts
parts[boneName].rotation.x
parts[boneName].rotation.y
parts[boneName].rotation.z
```

Offline converters should convert source matrices or quaternions into this runtime-friendly representation.

## Bone Names

Bone names must match `player.model.parts` keys exactly:

```text
hips
torsoContainer
torso
chest
neck
head
mouth
pelvis
leftArm
rightArm
leftForeArm
rightForeArm
leftHand
rightHand
leftThigh
rightThigh
leftShin
rightShin
shirt
```

Missing bones should be ignored safely by the runtime. Unknown bones should warn in development builds but should not crash gameplay.

## Notes For Future Tooling

The first converter should validate exported bones before writing JSON. Retargeting, foot anchoring, finger animation, face animation, and scale animation can be added after the basic JSON clip path is proven.
